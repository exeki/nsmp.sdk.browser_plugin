Целевой стек:
WXT
Vue 3
TypeScript

Сделать мессадж бандл для русского и английского. Реализация на усмотрение агента, но желательно что-то простое.

# Сборка и тестирование
- Минимум: Chrome 120+, Firefox 115+, Safari 17+ (macOS).
- Сборки: wxt build -b chrome | firefox | safari --mv3
- Safari (MVP): только ручная установка через Xcode / safari-web-extension-converter, без App Store.
- API: только browser.* (кроссплатформенно), без chrome-only.
- host_permissions: http://127.0.0.1/* и доступ к страницам NSD (/sd/admin/*).

# Совместимость

В целом по возможности нужно использовать максимально кроссплатформенные функции.

# Задачи

## Иконка
Базовая заготовка расположена по пути icons/nsmp_logo_colored.svg. 
Создавай свои версии и перемещай, если будет нужно. 

## Панель настроек
Нужно сделать отдельную вкладку с настройками. Переход на панель через extension popup
Все настройки плагина будет храниться там.
Текущий список настроек:
1. Переключатель языка (дефолт - язык браузера)
2. Порт локального сервера (дефолт - 8123)
3. Информация о локальном проекте (в виде таблицы)

Порт может быть от 0 до максимального порта. Если порт 0 — отключить все функции, связанные с локальным сервером.

## Popup

Popup открывается по клику на иконку расширения. Ширина — 320px, тема следует `prefers-color-scheme` (светлая/тёмная).

### Header
- Строка `SERVER:{port}` — порт из настроек.
- Круглая кнопка-индикатор: зелёная — сервер online, красная — offline. Клик выполняет ручную проверку (`GET http://127.0.0.1:{port}/`).

### Body
Три блока «label + value»:

**Current host**
- Hostname активной вкладки, если URL содержит сегмент `/sd/` сразу после хоста.
- Иначе — `none`.

**Project**
- Селектор проектов с локального сервера (`GET /projects`).
- В опциях: `{name} — {basePath}`.
- Список фильтруется по `installationHost === currentHost`.
- Выбор сохраняется в `browser.storage` как маппинг host → {name, path}.
- Ключ маппинга — hostname текущей вкладки.

**Current src**
- Код текущего исходника со страницы NSD (`#scriptModule:…`, `#script:…`, `#advImportConfig:…`).
- Обновляется при событии `URL_UPDATED` из background (смена вкладки / загрузка страницы).
- Если пользователь не на странице исходника — `none`.
- Кнопка **Pull** — `POST /pull` с телом:
```json
{
  "projectPath": "{{basePath из маппинга}}",
  "type": "{{module|script|advImport}}",
  "code": "{{код из hash}}"
}
```
- Pull disabled, если: нет исходника, не выбран проект, сервер offline или порт 0.
- На время запроса кнопка блокируется (loading).
- Результат — browser notification (успех / ошибка).

### Footer
- Кнопка **Settings** — переход на `options.html`.
- Название расширения.

### Связь с background
Background отслеживает активную вкладку и рассылает `URL_UPDATED` с URL. Popup подписан на это сообщение для обновления host/src/project.

## Нотификация
Плагин должен уметь реализовывать неблокирующие нотификации: информационные и об ошибках. 
Для этого нужна единая точка, которая будет либо взаимодействовать с каким 
то кроссплатформенным средством нотификации, либо для каждого браузера выполнять свой алгоритм нотификации.
Нотификации желательно сделать как Balloon Notification в левом нижнем углу на странице браузера. Они должны автоматически скрываться через заданный интервал времени.
Все информирование пользователя (как информационное, так и об ошибках) - через эту точку входа.

## Регулярное обновление информации с бекенда
На компьютере пользователя есть http сервис, который принимает запросы. Он может быть активен или не активен. 
Порт сервиса хранится в настройках.
Нужно при инициализации плагина проверять что сервис активен. Далее раз в 10 секунд делать запрос для проверки, что сервис активен или стал активен. 
Так же в расширении нужно сделать кнопку ручной проверки, кнопка в extension popup.
Когда сервис активен - иконка расширения должна быть текущего цвета. Иначе - серой.
Проверка происходит путем обращения на локальный порт http://127.0.0.1:{{port из настроек}}/ (всегда http при общении на локальный сервис) без пути.
Все запросы к локальному серверу — через `utils/localServiceConnector.ts`.
Сообщения между контекстами расширения — через типизированный протокол `utils/messages.ts`.
