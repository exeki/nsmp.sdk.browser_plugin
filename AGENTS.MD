# Стек
Это приложение - браузерное расширение. 
Целевой стек:
WXT
Vue 3
TypeScript

Сделать мессадж бандл для русского и английского. Реализация на усмотрение агента, но желательно что-то простое.

# Сборка и тестирование
- Минимум: Chrome 120+, Firefox 115+, Safari 17+ (macOS).
- Сборки: wxt build -b chrome | firefox | safari --mv3
- Safari (MVP): только ручная установка через Xcode / safari-web-extension-converter, без App Store.
- API: только browser.* (кроссплатформенно), без chrome-only.
- host_permissions: http://127.0.0.1/* и доступ к страницам NSD (/sd/admin/*).

# Совместимость
Chrome, Safari, Firefox
Все только на MV3.
Настройки хранить в browser.storage для обеспечения кроссплатформенности.
В целом по возможности нужно использовать максимально кроссплатформенные функции.

# Задачи

## Иконка
Базовая заготовка расположена по пути icons/nsmp_logo_colored.svg. 
Создавай свои версии и перемещай, если будет нужно. 

## Панель настроек
Нужно сделать отдельную вкладку с настройками. Переход на панель через extension popup
Все настройки плагина будет храниться там.
Текущий список настроек:
1. Переключатель языка (дефолт - язык браузера)
2. Порт локального сервера (дефолт - 8123)
3. Информация о локальном проекте (в виде таблицы)

Порт может быть от 0 до максимального порта. Если порт 0 - отключить все функции, связанные с локальным сервером (будет работать только история).

## Нотификация
Плагин должен уметь реализовывать неблокирующие нотификации: информационные и об ошибках. 
Для этого нужна единая точка, которая будет либо взаимодействовать с каким 
то кроссплатформенным средством нотификации, либо для каждого браузера выполнять свой алгоритм нотификации.
Нотификации желательно сделать как Balloon Notification в левом нижнем углу на странице браузера. Они должны автоматически скрываться через заданный интервал времени.
Все информирование пользователя (как информационное, так и об ошибках) - через эту точку входа.

## Регулярное обновление информации с бекенда
На компьютере пользователя есть http сервис, который принимает запросы. Он может быть активен или не активен. 
Порт сервиса хранится в настройках.
Нужно при инициализации плагина проверять что сервис активен. Далее раз в 10 секунд делать запрос для проверки, что сервис активен или стал активен. 
Так же в расширении нужно сделать кнопку ручной проверки, кнопка в extension popup.
Когда сервис активен - иконка расширения должна быть текущего цвета. Иначе - серой.
Проверка происходит путем обращения на локальный порт http://127.0.0.1:{{port из настроек}}/ (всегда http при общении на локальный сервис) без пути. 

## Указание локального проекта для текущего хоста
В параметрах расширения должен быть отдельный параметр, который устанавливается для каждого host (сайта, на котором происходит действие). Параметр будет в виде таблицы со столбцами: host, project name, project path.
Добавление новых строк или редактирование имеющихся всегда через popup. Пользователь должен на popup ввести хост (строку) и выбрать инсталляцию из предоставляемого локальным сервером списка.
Для редактирования или удаления добавить кнопки прямо в строки таблицы.
Кнопка добавить под таблицей.
Список можно получить по адресу:
GET /projects
Будет получен объект вида:
```json
{
  "projects": [
    {
      "name": "sdk_test",
      "basePath": "C:/projects/jvm/nsd/sdk/test",
      "isDisposed": false,
      "isInitialized": true,
      "nsmpSdk": {
        "installationId": "EXEKI1",
        "installationHost": "nsd1.exeki.local",
        "srcFoldersParams": {
          "projectAbsolutePath": "C:/projects/jvm/nsd/sdk/test",
          "scriptsRelativePath": "src/main/scripts",
          "modulesRelativePath": "src/main/modules",
          "advImportsRelativePath": "src/main/advimports"
        }
      }
    }
  ]
}
```
Из поля projects получить все объекты, которых поле nsmpSdk не пусто и предоставить пользователю выбор, перечисляя в опциях name + basePath (раздельно).
После выбора проверить, что для выбранного проекта installationHost соответствует указанному хосту (точное сравнение без учета поддоменов и ip), если нет - вывести нотификацию.
Если да - записать для текущего хоста name и basePath.


## Отображения истории 
Отслеживать url текущей странички. 
Если пользователь находится на страничке c путем:
/sd/admin/#scriptModule:*код модуля*
/sd/admin/#script:*код скрипта*
/sd/admin/#advImportConfig:*код импорта*

Если пользователь на одной из этих страничек, то нужно на страничке где то справа над контентом странички отобразить колонку с историей. Колонка должна быть разворачиваемой. Свернута она или нет должно храниться в хранилище браузера (глобально). 
Саму историю получить путем обращения по адресу:
{{текущая схема (http или https)}}://{{текущий хост}}/sd/services/rest/exec?func=modules.sdkController.getSrcHistory&params=request,response,user&page={{страница}}&pageSize=20&type={{script/module/advImport}}&name={{получается из url после двоеточия}}
Запрос выполнить из контекста вкладки что бы подтянулся jsession авторизации. 
В ответ будут возвращен список Dto вида:
```json
{
    "page": 1,
    "pageSize": 20,
    "total": 17,
    "items": [
        {
            "categoryName": "Добавление модуля",
            "category": "moduleAdd",
            "actionDate": "01.04.2026 19:56:21",
            "authorLogin": "system",
            "description": "Добавлен модуль '<a href=\"#scriptModule:sdkController\" class=\"link\">sdkController</a>'.",
            "uuid": "adminLogRecord$15704"
        }
    ]
}
```
Где:
```groovy
//Человеко читаемый тип события
String categoryName
//Код типа события
String category
//Дата события
Date actionDate
//Пользователь, выполнивший событие
String authorLogin
//Описание события, может быть очень большим
String description
//id события
String uuid
```
При нажатии на строку истории нужно открывать отдельную страницу по адресу:
{{текущая схема (http или https)}}://{{текущий хост}}/sd/admin/#adminLogRecord:{{uuid из элемента}}
Если сервер вернул ошибку - просто не отображать информацию, ошибку залогировать в консоль. 

При прокрутке подгружать еще элементы истории.
Каждый элемент отображать как строку, в которой две строки. В верхней строке: actionDate + authorLogin + categoryName, в нижней строке обрезанные первые 100 символов description, html теги удалить.
## Кнопка для загрузки исходника
Кнопка должна размещаться около истории и доступна по тем же условиям. 
При нажатии на кнопку: 
1. Блокировать кнопку до конца действия.
2. проверять, указан ли для текущего хоста проект. Если нет - попросить пользователя ввести при помощи popup (переиспользовать popup из раздела указания локального проекта), при этом предзаполнить host. 

3. После заполнения или если уже было заполнено, выполнить следующие шаги:
Выполнить запрос к локальному серверу
POST /projects/by-path
Тело:
```json
{
  "path": "{{сохраненный для хоста basePath}}"
}
```
Если вернется ошибка, попросить пользователя ввести проект (способ описан выше). 
4. Если вернется 200, то в теле ожидается ответ вида:
```json
{
  "project": {
    "name": "sdk_test",
    "basePath": "C:/projects/jvm/nsd/sdk/test",
    "isDisposed": false,
    "isInitialized": true,
    "nsmpSdk": {
      "installationId": "EXEKI1",
      "installationHost": "nsd1.exeki.local",
      "srcFoldersParams": {
        "projectAbsolutePath": "C:/projects/jvm/nsd/sdk/test",
        "scriptsRelativePath": "src/main/scripts",
        "modulesRelativePath": "src/main/modules",
        "advImportsRelativePath": "src/main/advimports"
      }
    }
  }
}
```
5. Проверить что installationHost соответствует текущем хосту (точное сравнение без учета поддоменов и ip). 
Если нет - вывести нотификацию с ошибкой и завершить процесс. 
6. Если да - выполнить запрос к локальному серверу:
POST /pull
Передать в тело запроса json:
```json
{
  "code": "{{код текущего элемента, находится после двоеточия}}",
  "type": "{{script/module/advImport}}",
  "projectPath": "{{basePath}}"
}
```
Если при запросе произошла ошибка - вывести нотификацию с ошибкой.
7. Если запрос успешен - вывести неблокирующую нотификацию о том, что pull задача успешно запущена.
