# План реализации браузерного расширения NSMP SDK

## Цель
Разработать функциональное браузерное расширение для интеграции с NSD, обеспечивающее кроссплатформенную работу в Chrome, Firefox и Safari (MV3) с поддержкой русского и английского языков.

## Технологический стек
- WXT (фреймворк для разработки расширений)
- Vue 3 (UI)
- TypeScript (язык)
- i18n (локализация)

## Этапы реализации

### Этап 1: Базовый Popup с визуальными плейсхолдерами

**Цель**: Создать основу для пользовательского интерфейса расширения.

**Файлы для модификации**:
- `entrypoints/popup/App.vue` - основной компонент popup
- `components/PopupContent.vue` - компонент с содержимым

**Действия**:
1. Упростить структуру `App.vue`, удалив логотипы WXT и Vue
2. Создать компонент `PopupContent.vue` с плейсхолдерами для:
   - Кнопки проверки состояния сервера
   - Секции настроек (язык, порт)
   - Секции управления проектом
3. Обновить импорты и ссылки на компонент
4. Реализовать поддержку темной темы через CSS-переменные и media query

**Верификация**:
- Проверить отображение popup при клике на иконку расширения
- Убедиться, что интерфейс отображает плейсхолдеры для всех ключевых функций
- Проверить автоматическое переключение между светлой и темной темой в зависимости от системных настроек

### Этап 2: Реализация системы локализации

**Цель**: Добавить поддержку русского и английского языков.

**Файлы для создания/модификации**:
- `locales/en.json` - английские сообщения
- `locales/ru.json` - русские сообщения
- `entrypoints/popup/composables/useI18n.ts` - хук для локализации
- Обновление `PopupContent.vue` для использования локализации

**Действия**:
1. Создать директорию `locales` с файлами сообщений
2. Реализовать простую систему локализации на основе browser.language
3. Интегрировать локализацию в компонент popup

### Этап 3: Система н��тификаций

**Цель**: Создать единое API для показа нотификаций.

**Файлы для создания/модификации**:
- `composables/useNotifications.ts` - хук для управления нотификациями
- `components/Notification.vue` - компонент отображения нотификации
- `entrypoints/popup/App.vue` - добавление контейнера для нотификаций

**Действия**:
1. Реализовать API для показа информационных и ошибочных нотификаций
2. Создать компонент нотификации в стиле balloon в левом нижнем углу
3. Обеспечить автоматическое скрытие через 5 секунд

### Этап 4: Управление настройками

**Цель**: Реализовать хранение и управление настройками.

**Файлы для создания/модификации**:
- `composables/useSettings.ts` - хук для работы с browser.storage
- `components/SettingsPanel.vue` - панель настроек
- Обновление `PopupContent.vue` для интеграции панели

**Действия**:
1. Создать систему хранения настроек в browser.storage
2. Реализовать панель настроек с полями:
   - Переключатель языка (по умолчанию - язык браузера)
   - Порт локального сервера (по умолчанию - 8123)
   - Таблица информации о локальных проектах
3. Реализовать валидацию порта (0-65535)

### Этап 5: Проверка состояния сервера

**Цель**: Реализовать мониторинг доступности локального сервера.

**Файлы для создания/модификации**:
- `composables/useServerStatus.ts` - хук для проверки сервера
- `background.ts` - добавление периодической проверки
- Обновление `PopupContent.vue` для отображения статуса

**Действия**:
1. Реализовать проверку доступности сервера по http://127.0.0.1:{port}/
2. Настроить периодическую проверку каждые 10 секунд
3. Реализовать кнопку ручной проверки в popup
4. Изменять иконку расширения (цветная/серая) в зависимости от статуса

### Этап 6: Управление проектами для хостов

**Цель**: Реализовать привязку локальных проектов к хостам.

**Файлы для создания/модификации**:
- `composables/useProjectMapping.ts` - хук д��я управления маппингом
- `components/ProjectMappingTable.vue` - таблица привязки проектов
- `components/ProjectSelector.vue` - селектор проекта из списка

**Действия**:
1. Реализовать получение списка проектов с локального сервера (/projects)
2. Создать таблицу с колонками: host, project name, project path
3. Реализовать механизм добавления/редактирования/удаления записей
4. При выборе проекта проверять соответствие installationHost и текущего хоста

### Этап 7: Отображение истории

**Цель**: Реализовать отображение истории изменений.

**Файлы для создания/модификации**:
- `content.ts` - модификация для внедрения в страницу
- `components/HistoryPanel.vue` - панель истории
- `composables/useHistory.ts` - хук для работы с историей

**Действия**:
1. Обнаруживать страницы с путями /sd/admin/#scriptModule:*, /sd/admin/#script:*, /sd/admin/#advImportConfig:*
2. Внедрять панель истории справа от контента
3. Реализовать получение истории с сервера NSD
4. Поддерживать состояние свернутости/развернутости в browser.storage
5. Реализовать подгрузку при прокрутке

### Этап 8: Кнопка загрузки исходника (Pull)

**Цель**: Реализовать функциональность загрузки исходного кода.

**Файлы для создания/модификации**:
- `composables/usePull.ts` - хук для операции pull
- Обновление `HistoryPanel.vue` для добавления кнопки

**Действия**:
1. Добавить кнопку рядом с панелью истории
2. Реализовать блокировку кнопки во время выполнения
3. Проверять наличие привязки проекта для хоста
4. При отсутствии - предлагать добавить через popup
5. Выполнять последовательные запросы к локальному серверу
6. Показывать статус операции через нотификации

### Этап 9: Финальная интеграция и тестирование

**Цель**: Обеспечить работоспособность всего функционала.

**Действия**:
1. Интегрировать все компоненты
2. Провести тестирование в Chrome, Firefox и Safari
3. Проверить кроссплатформенную совместимость
4. Убедиться в использовании только browser.* API
5. Проверить сборку для всех целевых браузеров

## Верификация
- Запуск `wxt build -b chrome`, `wxt build -b firefox`, `wxt build -b safari`
- Ручное тестирование основных сценариев
- Проверка отсутствия chrome-only API
- Проверка работы browser.storage
- Проверка отображения нотификаций
- Проверка обновления иконки расширения
- Проверка загрузки истории и работы кнопки pull
